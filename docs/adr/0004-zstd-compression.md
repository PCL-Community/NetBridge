# ADR-0004: zstd 流压缩（已否决——不引入）

日期：2026-08-20  
状态：**已否决（用户方向：无 zstd）**  
影响范围：历史记录

## 上一版内容摘要（不再适用）

上一版曾计划在 Rust 侧、QUIC 流之上做流式 zstd 压缩，并跳过原版 zlib `SetCompression`，作为可选能力（`zstd_stream`）。

## 为什么否决

- 用户明确要求**没有 zstd**，初期只做“传输能力识别 + QUIC 管道”。
- 任何压缩层都会改变字节流可观察性（压缩帧边界、zlib/zstd 状态）与吞吐特征，与“对其它 mod 透明”目标冲突。
- 原版 zlib `SetCompression` 照常运行（在 QUIC 流之上压缩 MC 帧），本项目不触碰。

## 现状

- 无 zstd、无原生压缩层。
- 原版压缩逻辑（`SetCompression`）原封不动，见 ADR-0001/ADR-0005。

## 未来（不承诺）

若后续需要压缩，可作为独立 ADR 重新评估（例如 rust-side zstd + 显式协商），但不在本项目初期范围。
