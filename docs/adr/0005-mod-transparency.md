# ADR-0005: 对其它模组的透明性边界

日期：2026-08-20  
状态：已接受（重写：无加密/压缩层后透明性更纯粹）  
影响范围：架构声明、测试、文档

## 背景与目标

用户要求：本项目初期对其它 mod **透明**。传输替换（TCP → QUIC 管道）在字节流语义上必须是“无感替换”。

## 透明性结论

### 1. 对“Connection 之上”的普通 mod：完全透明

- 依赖 MC 协议包/事件/字节流通用机制的 mod（聊天、物品、实体、任务、自定义兼容 payload、事件订阅等）只看到**与 TCP 一致的字节流语义**：
  - 协议状态机、帧长度、包顺序、压缩（原版 zlib）均不变；
  - 无额外加密层（原版 `enableEncryption` 照常）、无压缩层（无 zstd）；
  - `Connection`/Netty 管道语义保留。
- Ping 响应新增 `networks` 字段：未知 JSON 解析者忽略未知字段（向后兼容）。
- 因此这类 mod **无需任何适配**。

### 2. 对“同样接管传输层”的 mod：不承诺无条件共存

- ViaVersion、DirectConnection、反欺诈代理等同样替换/包装 `Connection` 工厂与管道的 mod，与 net-bridge **共享同一接管点**，mixin 顺序/契约可能冲突（与“同一文件两个 patch 不能同时应用”同类）。
- 缓解：
  - 明确“QUIC 接管可全局开关”（仅 TCP 行为）便于排查；
  - 文档化已知冲突清单；
  - 不承诺与独占传输管道的 mod 无条件共存。
- 这不属于缺陷，而是共享接管点的竞争。

### 3. 由于移除加密/压缩层，透明性更纯粹

- 移除 zstd、无 `encryption_skip`、无指纹后，**不再有任何改变字节流可观察性的层**，普通 mod 透明性最高。
- 无需登录期 flag 协商（ADR-0002 只保留 Ping `networks` 识别），因此不存在“登录协商拖垮其它 mod”的问题。

## 透明的实现原则

1. 不在字节流语义层做任何不兼容变更（帧、长度、压缩、加密状态与 TCP 完全一致）。
2. 所有传输层差异（QUIC/fallback、明文警告）仅存在于是物理路径与日志/状态。
3. 提供全局开关（禁用 QUIC）便于用户与 mod 排查。

## 后果与待办

- 文档化“支持共存 vs 已知冲突”清单。
- 建立 mod 透明性测试清单：聊天、实体、自定义 payload（NeoForge + Fabric）、status Ping 扩展字段、原版 zlib 压缩路径。
- 明确不承诺：与传输层独占 mod 的无条件共存。
